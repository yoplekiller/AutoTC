## 오늘 완료한 작업

### 1. TC Quality Gate 도입 (`src/generate_tc.py`)

GPT와 논의한 개선안을 검토 후 반영. AutoTC를 "AI가 QA 대신 TC를 쓰는 도구"가 아니라
"QA가 검토할 후보 TC를 사전 정제해주는 Test Design Assistant"로 방향 조정.

**타당성 평가 결론**: 원안(요구사항 추적/실행가능성 분류/PASS-REVIEW-REJECT 게이트 등)은
방향은 타당했으나, 문서 그대로(6개 하위 필드 quality_gate 객체, 공식 REQ-ID 체계, 구현물
기반 Gap Analysis까지)는 이 프로젝트 규모엔 과설계로 판단. Groq 무료 티어 TPD 한도를 이미
여러 번 소진한 이력이 있어 토큰 비용을 고려해 범위를 축소.

**적용 범위 (`generate_tc.py`만, `watch_sheet.py`는 이번엔 미포함)**:
- `augment_ticket_spec`: 요구사항에 `REQ-N` 번호 부여
- `_call_tc_api`: TC마다 `requirement_refs`/`requirement_status`/`execution_type`(7종 enum)
  /`required_tools`/`execution_note`/`test_design_technique`/`quality_status`(PASS/REVIEW/REJECT)
  /`quality_reason`을 LLM이 명시적 기준표로 자체 판정하도록 프롬프트 확장
- `sanitize_tc`: LLM 자기평가를 그대로 믿지 않는 규칙 기반 이중 체크 추가
  - `requirement_refs` 없는데 PASS/OK 자칭 → 강제로 REVIEW/NEEDS_CLARIFICATION 강등
  - 기대결과가 "정상적으로/올바르게" 등 추상 표현뿐인데 PASS 자칭 → REVIEW 강등
  - enum 밖 값(모델이 스키마 이탈 시) → 안전한 기본값 폴백
- `filter_tc_list`: quality_status가 REJECT여도 삭제 안 함(구조적 결함만 제거) — "수동 불가 =
  삭제" 금지 원칙 반영
- `dedupe_tc_list`: 시나리오 문구뿐 아니라 기대결과까지 합쳐 유사도 비교하도록 확장
- `save_excel`/`save_to_sheets`: Quality 판정/사유는 노출(색상+드롭다운), 나머지 메타데이터는
  기존 자동화가능여부 열과 같은 방식으로 숨김열 처리
- (부수 발견/수정) `--template` 플래그가 `input_str == "--template"`로 잘못 체크돼 항상
  무시되던 기존 버그 수정 (`args.template`를 봐야 함 — 이번 작업과 무관한 기존 결함)

**검증**: 가짜 TC 데이터로 회귀 테스트 작성해 실행 — 이 과정에서 실제 버그 2개 발견/수정
(requirement_status가 refs 유무 대조 없이 LLM 자기선언만 믿던 문제, 기대결과 모호표현
감지 정규식이 "1. " 번호 붙은 한 줄짜리에서 오작동하던 문제). `--template` 실행도 확인.

## 미해결 — 내일 이어서 할 일

### 1. 실전 E2E 테스트 미완료 (최우선)
MKQA-1로 `python src/generate_tc.py MKQA-1` 실행해 실제 Groq 응답으로 Quality Gate가
동작하는지 확인하려 했으나, **약 20분간 프로세스(PID 18084)가 멈춘 것처럼 보임**:
- 출력 파일 0바이트 유지, CPU 사용량 4회 연속 확인에서 전혀 안 늘어남(1.96s 고정)
- 처음엔 Groq(Cloudflare IP) 쪽 연결이 Established 상태로 유지되다가, 이후 확인에서는
  Jira/Groq 연결이 전부 사라짐(활성 연결 없음)인데도 프로세스는 살아있고 진행이 없었음
- 가장 유력한 원인: Groq 분당 Rate Limit(429) 재시도 백오프가 겹쳐서 길어진 것으로
  추정(`_call_tc_api`가 유형별로 최대 5~7번 호출되고, 실패마다 최대 65~195초 대기).
  다만 확실히 원인을 못 밝혔고, 진짜 행(hang)일 가능성도 배제 못 함
- 프로세스는 강제 종료하지 않고 그대로 둔 채 세션 종료함 — **내일 가장 먼저 확인**:
  1. 이 프로세스가 아직 살아있으면 강제 종료 후 재실행
  2. 재실행해도 똑같이 오래 걸리면 `rate_limit_wait_seconds` 백오프 로직이나 Groq
     쪽 상태(TPD 한도 소진 여부 등)부터 의심할 것
  3. 정상적으로 몇 분 안에 끝나면 이번엔 진짜 일시적 지연이었던 것으로 결론
